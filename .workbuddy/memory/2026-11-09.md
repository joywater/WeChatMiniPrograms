# 2026-11-09 工作日志

## 朗读语音全面升级（v1.1.8 已上传，包体 1.9MB / 2,011,961 字节）

**问题诊断**：用户反馈声音「不够符合宝宝喜欢的听觉」。实测当前链路 4 处损耗：
1. 音色 `101016` 智甜女童声 = 精品音色（传统参数合成），语调平、机械感；
2. `SampleRate=16000` → 高频上限仅 8kHz，童声清亮泛音被物理截断；
3. 16kbps MP3（v1.1.2 为控包体从 32k 降下）再砍一次高频；
4. `loudnorm I=-16:TP=-1.5:LRA=11` 压平动态范围，抹掉儿向语特有的夸张语调起伏；实测 mean −16.8dB / max −1.8dB 接近削波。
另：96 条 `say` 是解释型长句（「爷爷，爸爸的爸爸叫爷爷」「法官，法官公平又公正」），对 0-3 岁过于抽象。

**改动**：
- `utils/defaultData.ts`：96 条 `say` 全量改为儿向语（词名重复两次 + 叠词/拟声 + 3~6 字短句），平均 8.1 字符；去掉全部抽象关系与概念。10 条原本已合规的（如「乌龟，乌龟慢慢爬」）保持不变，实际写入 86 处。
- `scripts/gen_voice.py`：
  - `DEFAULT_VOICE=403000`（云小朵·特色女童声，超自然大模型 2.0，支持 24kHz）、`DEFAULT_SPEED=-0.6`、`SampleRate=24000`；
  - ffmpeg 链改为「裁首尾静音 → 50ms 淡入 → 3kHz +1.5dB EQ → `loudnorm I=-19:TP=-2:LRA=7` → 22k(实际被舍入为 24k)码率」；
  - 更新头部音色列表与计费说明（超自然大模型 2.0 为 2.5 元/万字符，免费包 2 万字符）。
- `utils/tts.ts`：新增 `gapTimer` 与 `GAP_MS=250`，连播每条播完停 250ms 再接下一条；`clearChain()` 同时清理计时器，保证单条播放/停止能打断连播。
- `package.json` 版本 1.1.7 → 1.1.8。
- 需求文档补全 v1.1.6/1.1.7/1.1.8 版本头与版本表，同步音色/采样率/目录结构/包体/决策记录（新增 15~17 条）与遗留问题。

**关键工程判断与踩坑**：
- **包体**：换 24kHz + 24kbps 后音频一度到 922KB，估算包体 2.12MB 超限。发现 TTS 返回自带约 0.45s 首静音 + 0.2s 尾静音（占单条 36%），用 `silenceremove` + `areverse` 裁到各留 0.1s（句间标点停顿完整保留），单条省约 18%，最终音频 800KB、包体 1.9MB，余量约 84KB。**音质与包体靠裁静音同时达成**，未降码率。
- **码率规格**：24kHz 采样的 MP3 合法 CBR 只有 8/16/24/32… kbps，`-b:a 22k` 会被 ffmpeg 舍入成 24k。VBR `-q:a 9` 二次转码仅省 7%，不划算，放弃。
- **未采用 SSML 停顿**：中文 SSML 兼容性不确定、有把标签读出来的风险，改用标点自然停顿 + 运行时 `setTimeout`。
- **未做运行时淡入/音量衰减**：淡入已在生成阶段用 `afade` 完成；响度已从 −16.8dB 降到 −20.2dB，再叠 `volume=0.85` 会二次衰减导致偏轻，故 `tts.ts` 只加间隔不动音量。
- **Git Bash MSYS 路径转换**：heredoc 里的正则 `\s` 被转成 `/s`，导致首轮批量替换 0 命中。改用 `id: *'...'` 不含反斜杠的写法。以后在 Git Bash heredoc 中写正则避免 `\s`/`\d`。
- **密钥**：用户提供腾讯云密钥，仅作行内环境变量传入，未落盘；建议轮换。
- 全量生成两次（一次 24k 无裁剪、一次加裁剪），96 条 0 失败；`tsc --noEmit` 通过；`node_modules` 与临时样本均已清理。
